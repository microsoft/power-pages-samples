# End-to-end tests

Dependency-free Playwright suites (plain `playwright` library + `@axe-core/playwright`, no test framework).

## Prerequisites

- Dependencies installed (`npm install`) — `playwright` and `@axe-core/playwright` are already in `package.json`.
- Microsoft Edge installed (the runner uses `channel: 'msedge'` and falls back to Playwright's bundled Chromium, which needs `npx playwright install chromium`).
- A running app:
  - dev server: `npm run dev` (default target `http://localhost:5173`), or
  - production build: `npm run build && npm run preview`, then pass its URL via `BASE_URL` or `--base-url` (e.g. `http://localhost:4173`).

## Running

```bash
npm run test:e2e      # all suites (smoke + flows + a11y + skeleton + ux)
npm run test:smoke    # access matrix + key partner flows
npm run test:a11y     # axe WCAG 2.2 AA scans

node tests/e2e/run.mjs --only flows                   # flows only
node tests/e2e/run.mjs --only skeleton                # skeleton loading states only
node tests/e2e/run.mjs --only ux                      # Practical UI review regressions only
node tests/e2e/run.mjs --only panels                  # contextual forms, mobile layout and draft recovery
node tests/e2e/run.mjs --only journeys                # SPA navigation, onboarding and hot-update context compatibility
node tests/e2e/run.mjs --only preload                 # navigation intent preloading (dev and production)
node tests/e2e/run.mjs --only lifecycle               # StrictMode, stale loads, cancellation and shared requests (dev only)
node --test tests/server/global-search.test.mjs       # actual Server Logic contract with controlled Dataverse responses
node --test tests/server/endpoints.test.mjs           # all 11 endpoints: failures, writes, paging, validation and totals
node tests/e2e/run.mjs --only widths                  # measured field/column alignment and responsive width policy
node tests/e2e/run.mjs --only confirmations           # confirmation copy, actions, descriptions and short-screen layout
node tests/e2e/run.mjs --base-url http://localhost:4173
BASE_URL=http://localhost:4173 node tests/e2e/run.mjs # same, via env
node tests/e2e/run.mjs --headed --workers 1           # watch it run
```

Options: `--only smoke|flows|a11y|skeleton|ux|panels|journeys|widths|confirmations|search|preload`, `--base-url <url>` (default `BASE_URL` or `http://localhost:5173`), `--headed`, `--workers <n>` (default 4).

Output is one `PASS`/`FAIL` line per check plus a summary; the process exits with code 1 if any check fails (2 for usage errors or an unreachable server).

## Conventions

- Technician suites inject a test-only contact and bookings through `prepareContext`; the template no longer ships a default Partner Technician sign-in persona. The removal regression also checks cleanup of previously saved mock accounts without resetting other records.

- Search regressions also exercise live-mode HTTP envelopes with controlled responses, including the actual `global-search` script through a Node VM. They cover literal four-word titles, partial/error states before and after Enter, retained local pages, keyboard Retry, registration failures, description-tail matches and aborted requests. These are contract tests, not proof of deployed Dataverse permissions. The lifecycle suite compares server and client ranking on Vite.
- The server contract tests run without a browser. They check matching, optional versus fatal failures, role-dependent query construction, latest registrations, ranking before result limits, and explicit warnings for the 500-candidate budget or a Dataverse continuation. Live search is deliberately bounded; a partial result is not an exhaustive count.
- `endpoints.test.mjs` executes all 11 real Server Logic scripts with controlled connector responses. It covers unsuccessful/malformed wrappers, empty-body writes, case-insensitive create-ID headers, uncertain writes without automatic retry, fresh authorization reads, required input validation, existing role boundaries, exact encoded continuation forwarding, cycle/row/page limits, failed workspace dependencies, primary-record 403/404 behavior and assistant totals beyond 100 opportunities. Complete reads stop at 20 pages or 10,000 rows with an explicit error, never a partial total. These tests do not establish deployed table permissions or real connector pagination support; validate those after an authorized deployment. Server Logic formatting retains semicolons because the SDK validator's return-expression check depends on them.
- Dataverse single-level expanded collections normally include a navigation `@odata.nextLink` without a paging token. That alone is not truncation. The endpoint tests preserve these responses and reject genuinely paged expansions or the documented 5,000-related-row ceiling, rather than silently treating incomplete relationship data as complete.
- The lifecycle suite also sends real endpoint outputs through the browser's live services: opportunity/account/contact creation, workspace mapping, uncertain-create errors and required-section failures. It checks that POSTs retain CSRF protection and uncertain creates are not automatically retried.

- `preload.mjs` (`--only preload`) checks the 100ms hover threshold and cancellation, focus and touch intent, shared create/edit screen imports, in-flight reuse, desktop/account menus, mobile navigation, active-descendant search navigation, and diagnosed speculative failures. It asserts that preloading does not navigate, mount a screen, change stored records or call business APIs. Run against production preview as well as the dev server to cover hashed chunks and Vite source modules.

- `search.mjs` (`--only search`) covers the top-bar global search and Partner assistant: focus expands the bar and hides the primary nav; zero-query groups (assistant prompts, popular/recent, quick actions); the debounced loading state, then the Ask row, inline Actions and grouped records; Enter → "Showing N results" with type filter chips; arrow-key `aria-activedescendant` selection opening a record and recording it under Recent; the create-opportunity customer prefill; Seller and anonymous scoping; the full-screen chat (fills the viewport, bottom composer, cited sources, follow-ups, Esc back to search with the query kept); mobile icon, Ctrl+K and `/`; the assistant widget modes (full screen → chat window → floating button and back, Esc minimizing the window, a cited link docking the chat while navigating, answers continuing while minimized with an unread indicator, the conversation surviving in-app navigation, mobile window bounds and 44px button); the always-visible circular Material 3 FAB (56px circle, icon only, elevation, 24px/16px margins, visible while scrolling, focus return, sitting above the save bar and hiding under page dialogs); and axe on each surface.
- `confirmations.mjs` covers compact dialog gutters, footer visibility, 48px targets, one-line desktop action labels, button contrast, associated consequence descriptions and safe focus at 1440x900, 320x844 and 320x380. It also verifies long-name keyboard scrolling, deactivation/Undo, reopening data, activation roles, named page/panel drafts, and truthful invitation/copy behaviour. Clipboard success/failure is simulated per test so tests do not overwrite the system clipboard.
- `widths.mjs` measures outer Fluent control boxes against their field columns at 1440/390/320px, verifies bounded settings/auth layouts, product-grid cells and error-state stability, compound address/invitation rows, partner-contact sidebar/Notes alignment and a representative long customer name. It checks geometry rather than merely testing CSS class names.
- `journeys.mjs` follows every available sitemap link and security navigation for all five personas without reloading between screens. It also covers live persona switching, application approval through a first deal, and colleague creation/invitation/redemption/profile updates with persistence after reload.
- It also verifies that old browser databases lose retired support/community collections and case comments without resetting active partner records or notes.
- Its two context regressions exercise deliberately different provider/consumer module URLs on the Vite dev server, reproducing hot-update version skew without touching source files. Run this suite against the long-running dev server as well as production: production runs exercise normal context integration, but cannot reproduce Vite's hot-module imports. Fresh-page production checks alone did not catch the original `UnsavedChangesProvider is required for draft protection` failure.
- `panels.mjs` is included in the full suite. It checks all 11 enabled contextual panel variants at desktop/mobile sizes with axe; dirty Escape/Cancel/close/backdrop; keyboard focus and restoration; coordinated page+panel Back recovery; native Enter submission without parent-form submission; address Apply versus record Save; lifecycle gating; and 320px short-height reflow. Tests measure actual panel/body/footer geometry, not just document overflow.
- The October 19 follow-up extends `ux.mjs` with main-form draft recovery, Back/Forward, create-and-select customer prerequisites, URL filter restoration, paging/count feedback, empty-state hierarchy, urgency ordering, and 48px targets on real coarse-pointer emulation at 320/390px. Tests may specify `contextOptions` to request touch/mobile browser contexts. New dialogs receive axe checks.
- Production skeleton delays target the tested page chunks only (`Home`, `OpportunitiesHome`, `CustomersHome`, `CustomerAccounts`, `CreateOpportunity`, `OpportunityDetails`, `OpportunitySummary`, `ProgramHome`, `BecomePartner`, `Profile`, `SignIn`), not vendor modules required to render the fallback.
- Each check runs in a fresh browser context. An init script sets the role (`contoso-partner-portal:role:v1`) and clears the stored database once per context (sessionStorage guard), so every check starts from seed data.
- `lifecycle.mjs` mounts isolated React hooks through Vite source modules with controlled live-mode responses. It checks record-key handoffs, obsolete reload callbacks, out-of-order responses, StrictMode cleanup, assistant cancellation and concurrent questions, shared-account request ownership, and non-overlapping keep-alive requests. Run it against the dev server; production runs explicitly report that this source-module harness is skipped. Existing search, confirmation and UX suites cover the rendered UI in either build.
- Any `pageerror` or console error fails the check, except the known Fluent dev warning containing "Keyborg" and failed loads of third-party (cross-origin) resources.
- Navigation is retried once when the dev server looks mid-rebuild (HTTP 5xx, empty `#root`, failed dynamic import); retries are printed as `note:` lines. A second failure is reported as a real failure.
- When pages change, update the expected `h1`/access matrix in `smoke.mjs` (also reused by `a11y.mjs`). Use role/label-based locators (`getByRole`, `getByLabel`) in flows.
