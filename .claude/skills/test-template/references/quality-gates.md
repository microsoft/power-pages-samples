# Template quality gates

New React SPA templates generated by `add-template`, or independently authored to the same repository contract, use
`qualityStandard: 1` in the manifest.
Existing released templates remain valid without that property until migrated.

## Required variant artifacts

Each quality-standard variant contains:

```text
website-code/
├── docs/
│   ├── a11y-reports/
│   │   ├── automated-<route>-desktop.html
│   │   ├── automated-<route>-mobile.html
│   │   └── accessibility-summary.json
│   ├── codeql-reports/
│   │   └── codeql-results.sarif
│   ├── design-review/
│   │   └── design-review.json
│   └── quality-manifest.json
├── tests/
├── playwright.config.ts
└── template-quality.json
```

Custom families must declare `seedDataPath` and ship representative non-sensitive seed data. Platform-only families
must not ship custom Dataverse solution or seed artifacts.

## Required local and repository checks

- Dependency restore from the committed lockfile
- Unit and service tests
- Typecheck and production build
- Playwright route, interaction, responsive, keyboard, console-error, and automated axe checks
- Playwright and axe-core scans for every declared route, state, and viewport against the local and deployed site
- Self-contained HTML generated from actual `AxeResults` with Microsoft's `accessibility-insights-report` package
- Automated accessibility score 100 with zero axe-core violations
- Repository-local exceptional-web-design review using real desktop/mobile previews and current source
- All ten design categories score 3 or 4, total 30-40, and every critical gate passes with evidence
- CodeQL JavaScript/TypeScript security-and-quality analysis with zero findings and no extraction errors
- Template validator
- Catalog build and inspection

## Required platform and consumer checks

- Complete permissions audit with a Safe to go verdict and zero major issues after authoritative platform artifacts exist
- Power Pages security review: Code & config before consumer acceptance, then Release readiness after activation
- Complete `plan-alm` environment-variable classification on the disposable consumer clone, with no committed credentials
- Clean consumer installation and live workflow verification

The committed exceptional-design scorecard, automated accessibility HTML, and CodeQL SARIF are evidence, not substitutes for rerunning checks.
`docs/quality-manifest.json` binds reports to the current source and seed data. A stale digest blocks completion.

The automated score covers only declared axe-core scans. It must not be described as full WCAG compliance;
Accessibility Insights assisted and manual Assessment requirements require human analysis.

Passing checks do not authorize environment work. An authoring workflow must obtain explicit contributor approval
before selecting an environment or invoking the consumer phase.
